# v1.2.17 - Security, clean URLs and resilient interactions (staging)

Prepared 6 November 2026. Unreleased staging candidate; target develop only.

## Visitor-facing changes
Routes use clean directory URLs instead of .html. Existing bookmarks receive
Cloudflare 301 redirects or portable HTML aliases that preserve queries and
fragments. Homepage staging stamping retains /preview/ and promotes its copy to
/, while production continues to serve the holding page.

Contact draft failures retain the visitor's input and offer the studio email.
Policy popups stop waiting after 15 seconds and offer the full policy page.
Image preview failures restore scrolling and fall back to the source image;
invalid dimensions are handled safely. Existing layouts, arrows and swipe
interactions are retained.

## Search metadata
Shared canonical URLs, Open Graph and Twitter metadata and organisation JSON-LD
use existing studio data. Staging remains noindex. No search ranking or immediate
indexing is promised; public launch indexing requires the documented launch step.

## Security and maintenance
GitHub Actions are pinned to commit SHAs and permissions are scoped per job.
CI tests freeze guards and diagnostics and audits dependencies. Dependabot targets
develop. Updated dependencies resolve the currently reported audit findings.
Production/rollback require main and fail closed while develop/FREEZE exists;
reaching 7 November does not remove the freeze automatically. These workflow
changes take effect on production only after a separately authorised main update.

Cloudflare static headers include nosniff, frame protection, referrer and feature
restrictions. CSP is report-only pending staging observation, not enforcement.
GitHub Pages does not consume _headers. Existing account MFA was confirmed by
the user; no account or hosting settings were changed.

Browser diagnostics record fixed codes and timestamps, capped at 20 per page.
They omit enquiry text, personal data, raw exceptions and URLs. There is no remote
collector or persistent logging service. Legacy redirect build failures exit
nonzero with an actionable message.

## Validation and remaining checks
Local build and staging stamping passed: 116 HTML pages, 46 projects and 151
photographs checked at 1.2.17. All eight automated tests passed (three version,
four deployment guard, one diagnostics); npm audit reported zero vulnerabilities.
A fresh npm ci was blocked by a Windows EPERM lock on the Astro compiler binding.
npm install restored dependencies and the subsequent build passed. CI must still
verify a clean npm ci installation.
Stamped staging checks explicitly use BUILD_ENV=staging and require noindex on
every route, including the relocated holding page.
Staging browser review, GitHub CI and live version.json verification remain
pending until push/merge/deployment. A successful build is not a live deployment.

merged commit, without marking it Latest. Never retarget existing v1.2.16.
Cloudflare failures are accepted as nonblocking by the user, but record actual
status and do not claim deployment without verification. Production main remains
611c1347909f9833ff84e39624c6b3de1e82e016 and FREEZE remains 2026-11-07.
Rollback via a revert PR into develop; previous staging baseline is v1.2.16.
